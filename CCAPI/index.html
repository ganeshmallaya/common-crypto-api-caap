01 / THE STRUCTURAL PROBLEM

Migration cost does not track the algorithm.
It tracks how many times someone typed its name.

The SHA-1 replacement needed no new interface and no new key format. It still took roughly a decade. Nothing about SHA-256 was difficult. The count was difficult.

0
places one identity platform names its signature algorithm

Post-quantum algorithms make the count worse. They change key sizes and signature sizes as well as names. An ML-DSA-65 public key is 1,952 bytes against 32 bytes for Ed25519. Code that assumed a size now fails beside code that assumed a name.

One migration is a project. Repeated migrations are a condition. This specification optimizes for the second migration, not the first.

03 / DEFINITION

What a Common Crypto API is.

A two-contract interface that separates the cryptographic operation a caller needs from the algorithm that satisfies it. Two properties define conformance. The caller cannot express an algorithm, and the algorithm can change without the caller changing.

↑ North contract

Faces callers

Carries operations only. Grows by addition within a major version, so a caller written today keeps working when the contract grows. A caller that can name an algorithm is not conformant.

GenerateKeyPair · Sign · Verify
Encapsulate · Decapsulate · Derive
Wrap · GetCapabilities · ResolvePolicy
↓ South contract

Faces backends

Any software library, network HSM, cloud key service, platform module, enclave, or smartcard that satisfies it registers as a provider. No core change is required to add one.

describe_capabilities · keygen
sign · verify · encaps · decaps
derive · wrap · attest

Neither contract references the other. That absence is the design. A new algorithm, a new appliance, or a policy change reaches production through the broker between them, and no caller changes.

07 / MATURITY MODEL

The call-site maturity model.

Other models measure organizational capability. This one measures a single physical fact: where the algorithm decision lives. That fact is observable, so every level carries a test an engineer can run this week.

Why the ladder stops at five. CS4 is the last level an interface specification can define. A system that discovers its own exposure, updates policy, and executes transformation with no human belongs to an orchestration layer above this contract. That layer deserves its own specification, and this document does not claim it.

08 / WHY THIS IS CRITICAL

The deadline is published. The recurrence is the real problem.

AUGUST 2024

The algorithms arrived

FIPS 203, 204, and 205 were published. The technical uncertainty ended and the migration clock started.

2027

Procurement gates close

New national security system acquisitions are expected to specify post-quantum algorithms. Procurement language moves before engineering does.

2030

Deprecation, and firmware signing goes exclusive

NIST IR 8547 proposes deprecating 112-bit public-key algorithms after 2030. CNSA 2.0 expects exclusive post-quantum software and firmware signing by the same year. Devices shipped today will still be in service.

2035

Disallowance

The same draft proposes disallowing those algorithms entirely. An estate that has not moved by then is non-compliant by definition rather than by assessment.

AFTER 2035

The part nobody plans for

Parameter sets will keep moving. An organization that treats this as one event pays the full cost again for every later revision.

Harvest now, decrypt later

An adversary can record encrypted traffic today and decrypt it once capability exists. Any data with a confidentiality horizon beyond five years is already exposed. Waiting is a decision with a cost.

Nobody has the count

No build system reports how many places name an algorithm. Discovery alone runs 12 to 24 months in a large estate. An organization cannot schedule work it cannot measure.

Verifiers lag signers

A signer cannot produce a signature nobody accepts. Every signature migration is gated by the slowest verifier, and some verifiers belong to customers.

Sizes break assumptions

Post-quantum keys and signatures are an order of magnitude larger. Fixed buffers, column widths, and packet assumptions fail in code that never named an algorithm at all.

09 / DECLARED BOUNDARY

What this architecture refuses to claim.

A specification claiming universal reach invites a reviewer to find the case it fails. A specification drawing its own boundary invites a reviewer to argue about where the boundary sits, which is the more useful conversation.

OUT OF SCOPE

Constrained devices. A microcontroller with 32 KB of memory cannot host a broker or reach a policy service.

OUT OF SCOPE

Boot-time roots of trust. A measured boot sequence verifies a signature before a network stack exists. It has nothing to ask.

OUT OF SCOPE

Line-rate datapaths. A datapath encrypting frames at line rate cannot afford a broker hop per frame.

NOT SOLVED

Verifier coordination. The architecture gives the signer one switch. It gives the verifiers nothing.

NOT SOLVED

Artifact size. A larger key is larger. This changes who selects the algorithm, not what it costs on the wire.

NOT SOLVED

Stored data. Where policy requires re-encryption, moving existing data is an operations program.

NOT SOLVED

Mandated algorithms. Where a scheme or regulator fixes the algorithm, resolution has one legal answer.

UNMEASURED

Latency. No published figure exists for a broker on a hot signing path at enterprise volume. This is the strongest reason to build the reference implementation before promising a number.

One asymmetry deserves attention. Firmware signing happens on a build server, which is an ordinary workload and fully in scope. Firmware verification happens on the device, which is out of scope. The signing side gains agility immediately. The verification side gains it only as the fleet turns over, and for medical or industrial equipment that takes a decade.
